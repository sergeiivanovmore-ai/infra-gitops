# Гигиена загрузки на Google Drive

Три ловушки, из-за которых загрузка «проходит», а пользователь не видит результат.

---

## 1. Захардкоженный ID + комментарий в коде — источник ложных выводов

В legacy-скриптах стояло `ROOT_FOLDER_ID = "1AGz0myzDGNX0oCq_fQJbOg2aboarOs35"  # 3dmodels`.
Первая сессия сделала вывод: «ID устарел, ведёт в пустую папку, загрузки уходили
в никуда» — и записала это в память.

**Вывод был неверным.** ID `1AGz0myz…` — это живая папка
`Мой диск / 3dmodels / veresk` (свойства `id` → `parents[]` подтвердили).
Неверен был **комментарий** `# 3dmodels` рядом с ним. Реальный `3dmodels` —
это `1B5IG-mIHgJdqUXqxANzfEDzXx0Z8pzbY`. Загрузки попадали в `veresk`,
то есть **куда-то осмысленное**, а не «в никуда».

| Что выглядит как баг | Что это на самом деле |
|---|---|
| «папка по ID пуста, ID протух» | ID указывает на **другую** папку; комментарий врёт |
| «загрузки молча уходили в никуда» | уходили в соседнюю по имени папку |

**Правило: разрешай ID в человеческий путь по `parents[]`, а не верь комментарию.**

```bash
python3 scripts/drive_tree.py --find "veresk"     # путь по ID
python3 scripts/drive_tree.py                      # дерево 3dmodels
```

```python
def human_path(fid, depth=8):
    """«Мой диск / 3dmodels / veresk» — единственный честный ответ на «куда это указывает»."""
    parts, cur = [], fid
    for _ in range(depth):
        f = get_meta(cur)                       # GET /drive/v3/files/<id>?fields=id,name,parents
        parts.append(f["name"])
        if not f.get("parents"):
            break
        cur = f["parents"][0]
    return " / ".join(reversed(parts))
```

**Перед любой загрузкой** перечисли структуру и зафиксируй цель:

```python
def children(fid):
    q = urllib.parse.quote(f"'{fid}' in parents and trashed=false")
    req = urllib.request.Request(
        f"https://www.googleapis.com/drive/v3/files?q={q}"
        f"&fields=files(id,name,mimeType,size)&orderBy=name",
        headers=H(), method="GET")
    with urllib.request.urlopen(req) as r:
        return json.load(r).get("files", [])

def find_folder(name):
    q = urllib.parse.quote(f"name='{name}' and trashed=false "
                           f"and mimeType='application/vnd.google-apps.folder'")
    req = urllib.request.Request(
        f"https://www.googleapis.com/drive/v3/files?q={q}&fields=files(id,name,parents)",
        headers=H(), method="GET")
    with urllib.request.urlopen(req) as r:
        files = json.load(r).get("files", [])
    return files[0]["id"] if files else None

# 0. Показать, что видишь на Drive — прежде чем что-либо куда-то класть
root = find_folder("3dmodels")
for sub in children(root):
    print(sub["name"], sub["id"], len(children(sub["id"])))
```

Признак устаревшего ID: `children()` возвращает **пустой список**, а ты уверен,
что папка непустая. Не создавай подпапку вслепую — сначала посмотри структуру.

## 2. Дубликаты: файл с тем же именем не перезаписывается

Drive **не перезаписывает** файл при загрузке с уже существующим именем — он
создаёт **второй файл**. При повторном прогоне пайплайна в папке оказалось
**8 файлов вместо 4**: мои новые (правильный кадр) плюс старые из прошлой сессии
(рендер занимал 25% кадра). Пользователь видит в папке кашу, где два разных
изображения носят одно имя.

**Правило: перечисляй целевую папку ДО загрузки.**

```python
existing = {f["name"]: f["id"] for f in children(target_folder_id)}
print("уже лежит:", len(existing))
# решение политики: перезаписать / переименовать / оставить
```

И **после** загрузки — обязательно перечислить снова и сверить число файлов
с числом частей. `len(files) != len(parts)` = вердикт, что что-то пошло не так.

## 3. Уборка: DELETE → корзина, не permanent delete

```python
def trash(fid):
    req = urllib.request.Request(
        f"https://www.googleapis.com/drive/v3/files/{fid}",
        method="DELETE", headers=H())
    with urllib.request.urlopen(req) as r:
        return r.status     # 204
```

`DELETE` без `?fields` кладёт файл в **корзину** — обратимо. Перед удалением
дубликата убедись, что он действительно старый: скачай один и сравни визуально
(`vision_analyze`) или по размеру.

## ⚠️ md5 FBX не является отпечатком геометрии

Два экспорта **одной и той же** геометрии дают FBX **одинакового размера, но
разный md5** — внутри файла лежат метка времени и уникальные идентификаторы.

Кейс: старый и новый `1.fbx` — оба 70 988 байт, md5 разные. Это **не** значит
«разное разбиение». Вывод «старый сплит отличается от моего» был бы неверным.

Как отличить старый рендер от нового, если имена совпадают:

| Признак | Вывод |
|---------|-------|
| размер отличается (537 КБ против 577 КБ) | разные настройки рендера |
| размер FBX совпал, md5 разный | вероятно та же геометрия, разное время экспорта |
| размер FBX и md5 совпали | это один и тот же файл |

## Порядок загрузки (полный)

```
1. resolve ID обходом Drive            (не хардкодь)
2. перечислить целевую папку            (найти дубликаты)
3. загрузить
4. round-trip: скачать обратно + md5    (verify_drive_roundtrip.py)
5. перечислить папку снова              (len == len(parts)?)
6. старые дубликаты → корзина
```

## 4. «В папке нет файлов» — файлы в подпапках, это по конвенции

Пользователь открыл `3dmodels/Дарио` и написал «в папке Дарио нет файлов».
Проверка API показала: в `Дарио` лежат ровно **две папки** — `models/` (211 FBX)
и `renders/` (211 PNG). Файлов **в корне модели нет — и не должно быть**.

Это ровно то же строение, что у `Penaly`, `Вильена`, `Спейс прямой, угл 1, 2`.
Конвенция проекта:

```
<исходная папка>/<Имя_модели>/
├── models/   1.fbx … 211.fbx
└── renders/  1_iso.png … 211_iso.png
```

**Правило: при жалобе «файлов нет» сначала показать дерево, а не спорить.**

```bash
python3 scripts/drive_tree.py --find "Дарио"
# печатает: id, полный путь, содержимое каждой подпапки
```

Ответ пользователю — **факты плюс прямые ссылки на подпапки**, а не «файлы
загружены». Человек кликает по ссылке и убеждается сам:

```
Дарио/models   — 211 файлов (1.fbx … 211.fbx)
Дарио/renders  — 211 файлов (1_iso.png … 211_iso.png)

https://drive.google.com/drive/folders/<id models>
https://drive.google.com/drive/folders/<id renders>
```

Не выдёргивай файлы в корень модели «чтобы было видно» — это ломает конвенцию
остальных папок. Если пользователь действительно хочет другое — пусть скажет,
и тогда дублируешь.

### Тот же класс ошибки: отчёт обрезан фильтром

Когда прогресс идёт в лог-файл, а наружу отдаётся `grep -E "ITEM|ALL_DONE"`,
пропадают строки `SKIP`. На Дарио это стоило лишнего вопроса «пропали ли
пропущенные предметы» — оказалось, 88 предметов просто помечены `SKIP (уже готов)`.
В отчёте всегда называй и `SKIP`-счётчик, и реальное число файлов на Drive.
