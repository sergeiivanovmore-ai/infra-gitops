# Ремонт разбиения: недо- и пере-сегментация

Кейс Дарио: 211 предметов, 2375 объектов. Пользователь нашёл в выгрузке ошибки
и попросил найти такие же и исправить.

## Два класса ошибок

| Класс | Что видит пользователь | Признак в данных |
|-------|----------------------|------------------|
| **Недо-сегментация** | один предмет разбит на 2–3 файла | узкий «осколок», bbox которого **перекрывается** с широким соседом |
| **Пере-сегментация** | в одном файле два предмета | внутри предмета компоненты разделены зазором ≥ 0.15 по X |

Список от пользователя (эталон для проверки детектора):

```
объединить: 10+11, 13+14, 20+21+22, 24+25+26, 28+29+30
разделить:  44, 88
206: левый элемент отдать 205, 207 присоединить к 206
```

## Почему X-зазоры бесполезны для диагностики

Первое, что я попробовал, — внутренние зазоры по X внутри предмета. **Не работает:**
у мебели панели одного шкафа перекрываются по X, поэтому зазоры почти все
отрицательные.

```
граничных разрывов < 0.05:  74 из 210
граничных разрывов < 0.20:  79 из 210
внутри №44: [-0.499, -0.491, -0.476, -0.468, ...]
внутри №88: [-0.999, -0.997, -0.493, -0.485, -0.029, ...]
```

**Единственная надёжная мера — связность в 3D**, а не проекция на ось.

## Алгоритм

### 1. Компонента = атомарный кусок мебели

Union-find по **пересечению 3D-AABB** всех объектов модели. Ребро ставится, если
перекрытие положительно по всем трём осям и **не только касание**:

```python
ox = min(a.x1, b.x1) - max(a.x0, b.x0)   # и аналогично oy, oz
if ox <= 0 or oy <= 0 or oz <= 0: continue
if ox < TOL and oy < TOL and oz < TOL:  # TOL = 0.02 — чистое касание
    continue
union(i, j)
```

У Дарио: 698 компонент из 2375 объектов.

**Ловушка:** одиночная компонента ≠ отдельный предмет. Разбивка `[8, 1, 1, 1]`
означает один шкаф и три отдельные мелочи (ручки, направляющие), а не четыре
предмета. Компонентные размеры сами по себе — плохой признак.

### 2. ПОРЯДОК: сначала разделение, потом склейка

Это главная тонкость. Наивный порядок «склеить → разделить» ломает требование
«левый элемент из 206 отдать в 205»: кусок отрезается уже после склейки и
остаётся отдельным предметом.

Правильный порядок:

1. **Разделить** каждый предмет по X-зазорам между компонентами,
   предварительно склеив компоненты с **перекрытием по X**
   (крышка и корпус одного шкафа по Z не пересекаются, но по X — да);
2. **Присоединить** осколки.

### 3. Правила

```python
GAP = 0.15      # минимальный зазор по X между разными предметами
SLIVER = 0.60   # ширина, ниже которой кусок считается осколком
HAIR = 0.06     # ультратонкая планка — присоединяется к ближайшему
```

**Разделение:** компоненты предмета с зазором ≥ `GAP` → разные предметы.

**Склейка (двусторонняя):** кусок с `width < SLIVER`, чей bbox **перекрывается**
по X с **более широким** соседом → присоединить к соседу. Ищи соседа с обеих
сторон — осколок может стоять и слева.

> Первая версия искала осколок только слева — и предмет №20 (осколок слева от 21)
> не склеился, хотя пользователь просил `20+21+22`.

**Ультратонкие планки:** после склейки остаются куски шириной 0.025 с одним
объектом, которые ни с чем не перекрываются (у Дарио — 7 штук). Их — к
ближайшему по центру, без условия перекрытия.

### 4. Валидация на эталоне пользователя

Обязательный шаг: прогнать правила на **известных** примерах и сверить
направление до/после. Совпало — детектор можно применять к остальным.

```

№14 (w 0.264) → №13              207 → №206
№20 (w 0.044) → №21
```

## 🚨 `items_index.json`: c0/c1 — это диапазон ЦЕНТРОВ

Самая дорогая ошибка в этой работе. `batch_split_render.py` назначает объект
предмету по условию:

```python
c0 - EPS <= center_x(obj) <= c1 + EPS
```

Поэтому в индексе `c0`/`c1` — это **min и max центров объектов предмета**, а НЕ
габариты предмета. Запись «`c0 = c1 = центр предмета`» даёт **все предметы пустыми**
(`ITEM 1/12 n=10 EMPTY`), и это выглядит как «модель сломалась».

```python
# ПРАВИЛЬНО
ctr = [(objs[q]["x0"] + objs[q]["x1"]) / 2.0 for q in members]
c0, c1 = min(ctr), max(ctr)
# для однообъектного предмета диапазон вырождается — расширить на полуширину
if c1 - c0 < 1e-9:
    c0, c1 = item_x0 + 1e-6, item_x1 - 1e-6
```

Перед сохранением индекса проверяй, что пересчёт по нему даёт **тот же** состав:

```python
bad = 0
for it in items:
    sel = [n for n, b in objs.items() if c0 - 1e-3 <= (b["x0"] + b["x1"]) / 2 <= c1 + 1e-3]
    if set(sel) != set(it["members"]):
        bad += 1
assert bad == 0
```
