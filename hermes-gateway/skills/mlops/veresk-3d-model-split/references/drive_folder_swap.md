# Замена содержимого папки Drive: upload-сначала, delete-потом

Кейс: у пользователя в `Дарио/models` и `Дарио/renders` лежало 211 файлов,
после ремонта разбиения стало 152. Пользователь попросил сначала **посмотреть**
(«загрузи новые рендеры на диск для проверки»), потом — удалить старое.

## 🚨 Почему нельзя «удалить старое, потом загрузить новое»

Скрипт `sync_drive.py` в рабочей папке начинался с:

```python
for label, parent in (("models", ID_MODELS), ("renders", ID_RENDERS)):
    for f in listdir(parent):
        trash(f["id"])          # сначала всё в корзину
# ...потом 152 загрузки по 1.5 сек каждая
```

Если загрузка упадёт на середине (сеть, 401, лимит) — папка останется
**полностью пустой**, а старая версия лежит только в корзине. Пользователь
увидит пустую папку и потеряет рабочий результат.

**Правильный порядок: сначала загрузить новое и проверить, только потом удалять
старое.** Стоимость — один лишний прогон загрузки. Цена ошибки — потерянный
результат.

## Процедура в три этапа

### Этап 1. Загрузить в отдельную папку (старое не трогаем)

```python
NEW = create_folder("renders_fixed_152", ID_DARIO)     # POST application/json
todo = [f for f in files if f not in {x["name"] for x in listdir(NEW)}]
for fn in todo:
    upload(os.path.join(RENDERS, fn), fn, NEW)         # multipart, resume-безопасно
```

Имя новой папки — с **номером итогового количества**: `renders_fixed_152`
читается как «исправленная версия, 152 предмета» и сразу отличает её от
рабочей `renders`.

Повторный запуск безопасен: `todo` считается как «на Drive ещё нет», поэтому
докачка после обрыва не создаёт дублей.

### Этап 2. Проверить ДО удаления старого

```python
remote = {f["name"]: int(f["size"]) for f in listdir(NEW)}
local  = {fn: os.path.getsize(os.path.join(base, fn)) for fn in files}
miss = [k for k in local if k not in remote]
bad  = [k for k in local if k in remote and remote[k] != local[k]]
extra= [k for k in remote if k not in local]
assert not (miss or bad or extra) and len(local) == EXPECTED
```

`assert` здесь — **блокирующий**. Если проверка не прошла, `sys.exit(1)`
**до** любых удалений.

### Этап 3. Подмена (только после подтверждения пользователя)

```python
for fid in (ID_MODELS_OLD, ID_RENDERS_OLD):
    for f in listdir(fid):
        trash(f["id"])          # DELETE → корзина, обратимо
time.sleep(3)                  # Drive бывает консистентным не мгновенно
rename(ID_MODELS_NEW, "models")
rename(ID_RENDERS_NEW, "renders")   # PATCH {"name": "..."}
```

`DELETE` без `?` кладёт файл в **корзину**, а не удаляет насовсем — откат
возможен. Перед удалением сохрани манифест id:

```python
json.dump([{"id": f["id"], "name": f["name"], "size": f.get("size")}
           for f in listdir(ID_MODELS_OLD)],
          open("/tmp/vil/backup_models_old.json", "w"), indent=1)
```

### Побочный эффект: остаются пустые старые папки

Drive не умеет переименовывать папку в имя уже существующей папки, поэтому
после `rename` в «Дарио» окажется **две папки с одинаковым именем** —
`models` (новая, 152 файла) и `models` (старая, 0 файлов).

Это нормально, но пользователь увидит дубли в боковой панели. Сказать ему
про это **до** подмены, а не после: «старые папки останутся пустыми, их можно
удалить вручную». Удалять их самому не надо — вдруг понадобится откат.

## Три грабли этого этапа

### 1. `?alt=media` отдаёт байты — их нельзя читать через `json.load`

md5 round-trip на выборке:

```
json.load(urlopen(...?alt=media))
→ UnicodeDecodeError: 'utf-8' codec can't decode byte 0x89 in position 0
```

`0x89` — это первый байт PNG-сигнатуры `\x89PNG\r\n\x1a\n`. Файл скачался
**целиком и правильно**, просто универсальная обёртка попыталась распарсить
его как JSON.

```python
def get(url, raw=False):
    d = urllib.request.urlopen(urllib.request.Request(url, headers=H),
                               timeout=300).read()
    return d if raw else json.loads(d)          # ← ветка для метаданных

data = get("https://www.googleapis.com/drive/v3/files/%s?alt=media" % fid, raw=True)
same = hashlib.md5(data).hexdigest() == md5f(local_path)
```

Правило: `?alt=media` — **всегда** `raw=True`. Метаданные (`files/<id>?fields=...`)
— `json.loads`.

### 2. Имена с суффиксом ломают `split(".")[0]`

```python
int(k.split(".")[0])        # "152_iso" → ValueError: invalid literal for int()
```

В skill уже есть строка про `f.split("_")[0]` на `45.fbx`; здесь зеркальная
ситуация — `152_iso.png`. Надёжно для обоих форматов:

```python
import re
nums = sorted(int(re.match(r"(\d+)", name).group(1)) for name in names)
# 45.fbx        → 45
# 152_iso.png   → 152
# 100_iso.png   → 100
```

### 3. Имя каталога ≠ имя каталога на Drive

Скрипт лежал в `.../dsh_model_split/Вильена/`, а грузил в папку «Дарио», и в
`id → get() → parents[]` подтвердилось, что общая папка — `Дарио`
(`1OEusjCLX6LGNo6gIiDeT99PVlfUjNfem`), а `models`/`renders` — её дети.

Рабочий каталог модели и папка Drive **не обязаны совпадать по имени**.
Всегда резолвить человеческий путь по `parents[]` через
`scripts/drive_tree.py --find`, а не по имени папки на диске.

## Когда уместен этот порядок, а когда нет

| Ситуация | Порядок |
|---|---|
| Пользователь хочет **посмотреть** результат перед заменой | upload в отдельную папку → пауза → подтверждение → delete + rename |
| Пользователь уже сказал «удали старое и замени» явно | те же три этапа, но без паузы: загрузил, проверил, подменил |
| Результат уже на Drive, правки не требуются | просто загрузка + round-trip |
| Результат **никогда** не доезжал до Drive | `drive_upload_hygiene.md` — резолв пути, дубликаты |

## Про уточняющий вопрос, на который не ответили

В этом кейсе я спросил через `clarify` «удалять ли старое?», ответа не пришло
за 10 минут. Но пользователь **уже дал явное указание** двумя сообщениями
раньше («Все верно. Удали старые рендеры и модели и замени их новыми»), а
действие было обратимым (корзина + манифест id).

Правило: если явное указание уже получено **раньше**, таймаут на
перепроверочный вопрос — не повод остановиться. Действуй по исходному
указанию, называй обратимость в отчёте («файлы в корзине, id сохранены в
`backup_models_old.json`»). Останавливаться стоит только когда решения
раньше не было.
