## 1. «Скрипт завис» — сначала определить, ЧТО именно не отвечает

Пользователь написал «опять скрипт завис». Диагностика велась в песочнице DSH —
и дала ложный вывод: каталог задачи не существует, blender не запущен, файлов нет.

**Проблема:** работа шла на **хосте** (`/opt/data/workspace/...`), а проверяли мы
**песочницу DSH**. Это разные namespace — пути DSH не видны с хоста и наоборот.

**Правильный порядок:**

```bash
# 1. локальный лог и состояние на ХОСТЕ — это первоисточник
ls -la --time-style=+%m-%d_%H:%M <workdir>/*.log
tail -5 <workdir>/batch.log

# 2. только потом DSH-задачи
task_list()
```

Признаки, что работа **уже завершилась**, а «зависание» — иллюзия:

| Признак | Значение |
|---|---|
| `ALL_DONE items=N assigned=M empty=0` + `Blender quit` + `EXIT=0` | успех, процесс отработал |
| `batch_watch*.json` с `"finished_reported": true` | сторож уже сообщил об окончании |
| время лога **позже** времени сообщения пользователя | работа шла, пока ты «ждал» |

**Задача DSH в статусе `running` — не доказательство работы.** Если её `cwd`
не существует, это «зомби» со ссылкой на стёртый каталог → `task_cancel()`.

### Рабочие пути и кириллица

```
workdir с кириллицей → терминал отклоняет:
  Blocked: workdir contains disallowed character 'В'
```

Обход — ASCII-симлинк, и **`workdir` указывать явно**:

```bash
ln -sfn "/opt/data/workspace/dsh_model_split/Вильена" /tmp/vil
cd /tmp/vil && ls -la
```

Если терминал падает с `cd: <dir>: No such file or directory` (умерший cwd
сессии) — передай явный `workdir`, например `/tmp`.

## 2. Уточление правил склейки: ширина — недостаточный признак

Первая версия правила была «宽度 < 0.6 → осколок». На Дарио это дало ложные
слияния (152 → 151 предмет — склеились **разные** шкафы).

**Правильный признак осколка — перекрытие, а не узость:**

> Осколок = узкий предмет, чей bbox **перекрывается** с более широким соседом.

Узкий предмет с **положительными зазорами с обеих сторон** — это реальная
мебель (тумба-панель шириной 0.5), и склеивать его нельзя. На Дарио таких
12 штук, зазоры 0.17–0.63.

**Порядок операций обязателен: сначала РАЗДЕЛЕНИЕ, потом СКОЛЕЙКА.**
При обратном порядке отрезанный кусок не доедет до соседа: пользователь просил
«левый элемент из 206 → в 205», а 206 предварительно разрезали.

**Дефект в правиле, найденный на своих же примерах:** поиск осколка только
**слева** пропускал случай, где осколок лежит **слева** от жертвы (предмет 20
относительно 21). Ищи соседа **с обеих сторон**.

## 3. Анимационные дубли — класс, который правила склейки не ловят

После ремонта нашлась пара предметов с анимационным дублем:

- №111 — тумба, ящик **закрыт**
- №112 — та же тумба, ящик **выдвинут**

Зазор между ними **0.121** — меньше порога склейки, но bbox **не перекрываются**,
поэтому правило «перекрытие» их не поймало.

**Признак кандидата в анимационный дубль:**

```
зазор между соседями < 0.15 (порог склейки)
  И
почти одинаковые габариты / высота / материал
  → подозрение: один предмет в двух состояниях анимации
```

**Обязательная проверка — `vision_analyze` обоих рендеров.** Только глазами
видно, что это ящик в двух положениях, а не два разных предмета.

**Чего делать НЕ надо:** не искать дубли по сходству имён объектов. На Дарио
проверка «общих базовых имён» дала **447 ложных пар** (имена вида `Object507`
сводятся к `Object` и совпадают у всего). Этот тест бесполезен.

Если анимированной мебели много, проход по таким парам — отдельная задача
со склейкой и пересборкой, а не разовая проверка.

## 4. Приёмка большой пересборки: инварианты вместо ручного просмотра

152 файла глазами не проверить. Докажи полноту числами.

### 4.1 Файлы на месте и без дыр

```python
import os, re
for sub, ext in [("parts_fixed", ".fbx"), ("renders_fixed", "_iso.png")]:
    p = os.path.join(D, sub)
    fs = os.listdir(p)
    nums = sorted(int(re.match(r"(\d+)", f).group(1))
                  for f in fs if re.match(r"(\d+)", f))
    print(sub, len(fs), "мин", min(nums), "макс", max(nums))
    print("  пропущено:", [i for i in range(1, 153) if i not in set(nums)] or "НЕТ")
    print("  мелкие:", [f for f in fs if os.path.getsize(os.path.join(p, f)) < 2000] or "нет")
```

`renders_fixed` лежит рядом с `parts_fixed`, а **не** в `models_fixed` — сверь
реальные имена каталогов через `ls` до проверки, а не по памяти.

### 4.2 PNG валидны (проверка сигнатуры, а не размера)

```python
import struct
for f in os.listdir(p):
    h = open(os.path.join(p, f), "rb").read(33)
    assert h[:8] == b"\x89PNG\r\n\x1a\n" and h[12:16] == b"IHDR"
    w, hh = struct.unpack(">II", h[16:24])
    assert (w, hh) == (1024, 1024)
```

### 4.3 Геометрия не потеряна

```python
d = json.load(open("items_repaired.json"))
items = d["items"]
assert len(items) == 152
assert sum(len(it["members"]) for it in items) == d["n_objects"]   # 2375
assert not [it["n"] for it in items if not it["members"]]           # пустых нет
assert len({it["n"] for it in items}) == len(items)                # дублей нет
```

### 4.4 Главный инвариант чистоты: ноль перекрытий между соседями

```python
items = sorted(items, key=lambda x: x["x0"])
overlaps = [(a["n"], b["n"], round(b["x0"] - a["x1"], 3))
            for a, b in zip(items, items[1:]) if b["x0"] - a["x1"] < 0]
print("перекрытий:", len(overlaps))   # должно быть 0
```

**Ноль соседних пар с перекрытием по главной оси** — сильнейшее доказательство,
что незакрытых осколков не осталось. На Дарио дало `0`.

Плюс список подозрительно близких соседей (`0 <= gap < 0.15`) — это кандидаты
в анимационные дубли из раздела 3.

### 4.5 Сверка «склейки записана правильно»

`merged` хранится как словарь `источник → цель`. Прогони по **всем** примерам
пользователя и сверь направление:

```python
for src, dst in d["merged"].items():
    print(f"№{src} -> №{dst}")
```

Ожидаемо: `11→10, 14→13, 20→21, 22→21, 24→25, 26→25, 28→29, 30→29`,
а после разрезаний — `206→205` (левый элемент) и `207→206`.

## 5. Отчёт пользователю после ремонта

Обязательно показать:

- **было → стало** (211 → 152), сколько разделено, сколько склеено;
- **инвариант потерь**: 2375 объектов, сумма `members` == `n_objects`, пустых нет;
- **чистоту**: ноль перекрытий между соседями;
- **проверку глазами** ключевых случаев (несколько рендеров через `vision_analyze`);
- **отступление от формулировки**, если оно было (пользователь написал
  «24+24+26» — истолковано как 24+25+26), с явной оговоркой;
- **что осталось незагруженным**: новые файлы лежат в `parts_fixed/` /
  `renders_fixed/`, на Drive старая версия, ждёт решения пользователя.

Не выдавай «проверку глазами» за выполненную: рендеры 10–15 затронутых
предметов смотреть нужно реально, до отчёта.
