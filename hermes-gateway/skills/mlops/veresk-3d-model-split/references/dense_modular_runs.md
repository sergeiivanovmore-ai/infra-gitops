# Плотные модульные ряды: когда разделение по зазорам не работает

Кейс: **Вильена.fbx** (75 МБ, 1069 объектов) — модель, где оба автоматических
метода дали мусор, и разметку пришлось отдать пользователю глазами.

---

## Симптомы: модель «не режется»

| Признак | Значение |
|---------|----------|
| span по главной оси **в разы** больше остальных | 134.3 × 1.05 × 2.73 — не шкаф, а длинный ряд |
| `gaps_top[0].gap_pct` меньше 1–2% | зазоров между модулями фактически нет |
| `planned_parts` (auto) >> 20 | по «зазорам» нарезаются сотни осколков |
| Объекты тысяч, а модель одна | сцена, а не единое изделие |

## Реальные цифры Вильены

```
объектов:            1069
полный bbox:         134.3269 × 1.0463 × 2.7289
устойчивый bbox:     128.1934 × 0.8118 × 2.1268   (по 98% центров)
выбросов:            58
зазоров найдено:     178
крупнейший зазор:    0.8934 = 0.70% длины
auto-сегментация:    181 часть   ← мусор
detect_modules.py:   472 группы, из них 381 одиночка (1–2 объекта), 91 с 3+ объектами
```

### Почему зазоры не работают
Модули стоят **вплотную**: панели соседних корпусов смыкаются. Крупнейший
зазор — 0.7% длины, это не стык модулей, а технологический зазор.

### Почему не работает объединение по перекрытию
Пытались объединять объекты в группы по перекрытию габаритов (union-find):
панели одного шкафа перекрываются, но **и панели соседних шкафов смыкаются**.
Итог — не модули, а 91 обломок и 381 одиночный объект (фурнитура, ручки).

**Вывод: для плотно стоящей модульной мебели автоопределение модулей нереально.**
Не выдавай пользователю 91 обломок как «готовые модули».

### Что удалось вытащить
- Корпуса идут **парами**: одинаковая позиция X, разная глубина (0.50 и 0.98)
  → похоже на два ряда, основной и выступающий
- Ширина модулей **растёт** слева направо: от 0.8 до 3.0
- Высоты 2.2 / 0.75 / 0.50 / 0.38 — разные типы: высокие шкафы, тумбы, полки

## Диагностическая лестница

### 1. Устойчивые габариты вместо bbox
```bash
blender --background --python analyze_spatial.py -- --input model.fbx
```
Печатает `ANALYSIS_JSON`: полный и устойчивый bbox (по 95–98% центров),
список выбросов, главную ось, число и ширину зазоров.
Печать: `objects_total / objects_main / objects_outliers`, `robust_span`, `gaps_top`.

### 2. Попытка найти модули структурно
```bash
blender --background --python detect_modules.py -- --input model.fbx
```
Печатает `MODULES_JSON` с группами и их габаритами. Использовать **только как
разведку**: смотри, вырисовывается ли ритм. Если `modules_found` в разы больше
видимых на рендере предметов — метод не сработал, не навязывай результат.

### 3. Обзорный рендер — панорама фронтального вида
```bash
blender --background --python render_parts.py -- \
    --models-dir <dir>/input --out-dir /tmp/pan --select "Вильена" \
    --samples 32 --res-w 3000 --res-h 620 --view front --suffix _front
```
**`--view front` обязателен** для длинных линейных моделей: изометрия даёт
уходящую вдаль диагональ, по ней невозможно считать модули.

### 4. Крупные фрагменты для выбора
```bash
for i in 0 1 2 3 4 5; do
  blender --background --python render_parts.py -- \
    --models-dir <dir>/input --out-dir /tmp/slices --select "Вильена" \
    --samples 24 --res-w 900 --res-h 700 --view iso \
    --slice "$i/6" --suffix "_s$i"
done
```
`--slice I/N` оставляет только объекты в I-й полосе из N вдоль главной оси
и кадрирует по ней — даёт зум без потери разрешения.

## Ловушка кадрирования

Модель с пропорциями 50:1 (`134 × 1 × 2.7`) в **квадратном** кадре 2048×2048
превращается в тонкую диагональную полоску — выглядит как «модель сломалась»,
хотя она в порядке.

```
aspect = res_w / res_h
```

**Правило: пропорции кадра задавай под пропорции модели.** Для линейных рядов —
`--res-w 3000 --res-h 620`. Не суди о модели по квадратному рендеру
вытянутого изделия.

`--view` поддерживает `iso` (по умолчанию), `front`, `top`.

## Что показывать пользователю

Не выдавай 181 осколок и 91 обломок как готовое решение. Покажи картинку и
предложи **три осмысленных варианта** (для Вильены):

- **Вариант А — по парам корпусов:** нарезать по X на N равных участков, чтобы
  в каждый попали оба ряда (глубина 0.5 и 0.98)
- **Вариант Б — по конкретным диапазонам:** пользователь сам назовёт границы
  по фрагментам (например «первые 2 фрагмента → 3 части, остальные 4 → 5 частей»)
- **Вариант В — по глубине:** разделить на два ряда (выступающий 0.98 и основной 0.50)

И уточни формат: фронт, верх, или сильное приближение на стыки.

### Помни про `--select`
В `render_parts.py` и `analyze_*` ключ `--select` — имя **без расширения**
(`Вильена`, не `Вильена.fbx`). Не совпадёт — скрипт **молча** отрендерит пустоту.
