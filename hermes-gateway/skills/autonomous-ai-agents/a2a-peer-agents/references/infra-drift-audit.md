# Сверка фактической инфраструктуры с документом-эталоном

Задача: «сравни текущее состояние Docker/сервера с ARCHITECTURE.md и покажи расхождения».
Выполняется через пира (`sysadmin`) — он единственный имеет доступ к Docker-хосту.

## Порядок

1. **Найти эталон** — не угадывать путь. Спроси пира прямо: «существует ли файл эталонной
   архитектуры и где он лежит?» Он отдаст путь, размер и дату (типовое место —
   `/opt/data/ARCHITECTURE.md`; локально из контейнера оркестратора этот файл может быть
   НЕ виден — `read_file` вернёт «File not found»). Затем попроси ПОЛНОЕ содержимое
   дословно, чтобы сверять своими глазами.
2. **Собрать факт одним запросом**: `docker ps -a --format '{{.Names}} | {{.Image}} | {{.Status}} | {{.Ports}}'`,
   `docker network ls`, и сети по контейнерам через
   `docker inspect -f '{{.Name}} {{range $k,$v := .NetworkSettings.Networks}}{{$k}} {{end}}' $(docker ps -aq)`.
   Published-порты дополнительно подтверждай `docker inspect` (в `docker ps` колонка Ports
   бывает пустой).
3. **Таблица расхождений**, по строке на каждое: `что | эталон | факт | тип | комментарий`,
   где тип — «отсутствует в эталоне» / «отсутствует в факте» / «несовпадение». Отдельно
   отметь недокументированные сети, незаппубликованные порты (объявленный EXPOSE ≠ опубликован)
   и loopback-bind (`127.0.0.1:host→cont`).
4. **Диаграмма:** mermaid `graph TD`, где расхождения помечены красным через
   `classDef bad`/`netbad` (подсветка), эталонное — синим. Группировать по сетям
   (`subgraph`), в узлах — имя, образ/порты. Показывай ОБЕ стороны: что совпало и что
   разошлось, а не только «список проблем».
5. **Правка эталона — только после явного подтверждения пользователя.** Порядок:
   бэкап `ARCHITECTURE.md.bak-<дата>` + поднять версию и дату в шапке; внести фактические
   драйверы сетей, сети по контейнерам, реальные published-порты, bind-адреса, лишние
   контейнеры; устранить внутренние противоречия документа.
6. **Проверка:** запроси у пира версию в шапке и наличие `.bak` — самоотчёт о правке
   проверяй этим, а не доверяй ему.

## Замечания

- Остановленный контейнер (`Exited (255)`) — это расхождение «отсутствует в эталоне», а
  удаление — деструктивная операция, её подтверждает пользователь.
- Служебные сети (`bridge`, `host`, `none`) тоже перечисляй — иначе таблица «9 сетей»
  выглядит как «7 недокументированных» без объяснения.
- Финальный рендер диаграммы — см. `mermaid-render-to-png.md`.
