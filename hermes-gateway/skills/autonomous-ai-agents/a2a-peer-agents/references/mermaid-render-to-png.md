# Mermaid → PNG без локального mmdc

Когда пир вернул mermaid-код (или его `.mmd` лежит в его workspace), а рендерить нечем:

## Рецепт

1. Запиши код в файл через `write_file` (например `/opt/data/cache/scratch/mmd/arch.mmd`).
   Хелперы без этого шага ломаются на heredoc — файл надёжнее.
2. POST в kroki.io (без ключей и установки):
   `curl -sS --max-time 60 -X POST -H 'Content-Type: text/plain' --data-binary @arch.mmd https://kroki.io/mermaid/png -o arch.png -w 'http=%{http_code}\n'`
   Эндпоинт `/mermaid/png` рабочий; `/mermaid/svg` может отвечать 500 — не считай это
   ошибкой входных данных, просто бери PNG.
3. Всегда проходи `workdir` явно у терминальных вызовов и используй абсолютные пути:
   дефолтный cwd сессии может не существовать, и тогда падает даже `mkdir`/`cd` первой
   строки скрипта.

## Проверка без PIL и без vision

PNG декодируется чистым Python:

```python
import zlib, struct
d = open(path, 'rb').read()
assert d[:8] == b'\x89PNG\r\n\x1a\n'          # сигнатура
w, h = struct.unpack('>II', d[16:24])          # размеры из IHDR
```

Плюс развёртка IDAT с фильтрами (0=none, 1=sub, 2=up, 3=avg, 4=paeth) даёт число
«чернильных» пикселей — так подтверждается, что рендер не пустой.
Это проверка структуры, НЕ читаемости текста: русские подписи в узлах визуально ею не
подтверждаются. Если vision-эндпоинт недоступен — скажи в отчёте «рендер валиден, глазами
не проверен» и предложи альтернативу (локальный SVG/HTML с DejaVu + скриншот браузером),
вместо того чтобы выдавать картинку за проверенную.

## Где взять mermaid-код, если пир его не отдал

`.mmd` обычно остаётся в workspace пира (`/opt/data/workspace/<name>.mmd`) — попроси путь
и содержимое отдельным коротким запросом.
