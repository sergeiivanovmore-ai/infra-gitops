# hermes-orchestrator: работа с мостом DeepSeek Harness

Источник истины для инструкций оркестратора по DSH. Деплой копирует файл в
/opt/docker/hermes-orchestrator/data/AGENTS.md. Менять только через PR.

## Подключение

Сервер называется dsh-carrot (см. agents/hermes-orchestrator/settings/mcp_servers.yaml),
адрес http://dsh:8090/mcp, авторизация — переменная окружения MCP_DSH_CARROT_API_KEY.
Фильтра инструментов в этом подключении нет: доступны все средства моста.
Вызовы выглядят как mcp__dsh-carrot__<имя средства>, например mcp__dsh-carrot__session_create.

## Имени agent_run больше нет

Оно существовало в линии моста 0.1.x. Сейчас запуск работы — это пара вызовов, а не один:

1. model_list — что доступно: модели и пресеты.
2. session_create — обязательны cwd, provider, model и preset; по умолчанию ничего не подставляется.
   permission задаёт пресет прав, например workspace-write.
3. session_prompt с тем же sessionId — синхронный ход, ждёт завершения.

Если ход длинный и не укладывается в ожидание MCP: session_submit, затем session_poll по статусу
и session_result — полный результат забирается один раз. Отмена — session_cancel.

## Как читать результат

status, toolCallCount, toolResultCount, changes, verification, leftovers,
ресурс вида dsh://sessions/<id>/history.
toolCallCount при completed, равный нулю, означает: мост жив, а работа не сделана.
Докладывать такую задачу как выполненную нельзя.

## Подтверждения

approval_list показывает ожидающие подтверждения, approval_answer отвечает на них.
Ждать бессмысленно: срок 120 секунд, и запрос отваливается.
Чёрный список (запись креденшелов, установка плагинов, доверие соединений) подтвердить нельзя.

## Проверка себя

dsh_status — версия моста, порт, режим авторизации, число подключений.
Ресурсы dsh://models, dsh://presets, dsh://workspaces доступны без вызова инструментов.

## Правила дома

- Pull Request — да, мерж — нет; мержит человек.
- Значения ключей не печатать: только имя переменной и отпечаток.
- Остановка и удаление контейнеров, правки живых конфигов — только через PR или по решению человека.
- Сессия моста переиспользуется по паре (каталог, модель), поэтому параллельные задачи
  выстраиваются в очередь — это нормально, а не отказ.
