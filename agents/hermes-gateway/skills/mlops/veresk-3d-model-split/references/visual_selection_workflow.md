# Визуальный выбор: сначала картинка, потом разделение

Пользователь просит именно этого — и просит **дважды**, поэтому это не разовое
каприз, а способ работы: *«сделай рендер и пришли, я выберу что разделять»*,
*«пришли один общий рендер, я скажу сколько там моделей и какие выделить»*.

---

## Когда предлагать визуальный выбор

| Ситуация | Что делать |
|----------|------------|
| Пользователь прямо попросил рендер для выбора | сразу визуальный выбор, не предлагай прогноз |
| `gaps_top[0].gap_pct` < 1–2% | визуальный выбор (см. `dense_modular_runs.md`) |
| Изделие составное: ряды, углы, поворотные секции | спроси: «отрендерю для выбора?» |
| Пользователь не доверяет цифрам | визуальный выбор |

**Не смешивай:** не выдавай прогноз «181 часть» и не начинай рендерить все
фрагменты, пока пользователь не подтвердил, что хочет выбирать глазами.

---

## Обязательное правило: проверь картинку сам, до отправки

**Отправленные рендеры не должны проверяться пользователем за тебя.** В этой
сессии 6 фрагментов были отправлены без проверки; при проверке выяснилось,
что модель — это не «шкаф», а ряд корпусов с **распахнутыми под разными углами
дверями**, и именно это ломало всё разделение. Пользователь получил бы
бесполезные картинки и потратил время на выдачу неверного решения.

```bash
# перед отправкой — ОДНА проверка
python3 - <<'EOF'
from hermes_tools import vision_analyze
print(vision_analyze("/tmp/pan/Вильена_front.png",
      "Что здесь? Считаются ли отдельные предметы? Кадр не пустой?"))
EOF
```

Что проверяем: кадр не пустой, модель не в обрезании, **предметы различимы**,
не видно ли очевидного брака (модель в пустоте, кадр смещён, всё в полях).

## Как сделать картинку читаемой (и пережить сжатие Telegram)

### Проблема 1: квадратный кадр убивает вытянутую модель

Модель 50:1 (`134 × 1 × 2.7`) в кадре 1024×1024 → тонкая диагональная полоска.
Решение — пропорции кадра под модель:

```bash
blender --background --python render_parts.py -- \
    --models-dir <dir>/input --out-dir /tmp/pan --select "Вильена" \
    --samples 32 --res-w 3000 --res-h 620 --view front --suffix _front
```

### Проблема 2: даже правильный кадр пустует на ~90%

При `--res-w 3000 --res-h 620` модель занимает **~10% высоты**: по вертикали
в кадр влезает ~24 единицы, а модель высотой 2.7. Пиксели тратятся впустую.

### Проблема 3: Telegram пережимает широкое изображение

Telegram ужимает фото по длинной стороне. Панорама 3000×620 при доставке
превращается в ~1400×290 — модули снова сливаются.

### Решение: рендер срезами + обрезка по альфе + склейка

```bash
# 1. рендерим модель двумя срезами в высоком разрешении
for i in 0 1; do
  blender --background --python render_parts.py -- \
    --models-dir <dir>/input --out-dir /tmp/h --select "Вильена" \
    --samples 48 --res-w 3200 --res-h 900 --view front \
    --slice "$i/2" --suffix "_h$i"
done

# 2. обрезаем пустые поля по альфе и склеиваем в ОДНУ картинку
blender --background --python stack_images.py -- \
    --inputs "/tmp/h/Вильена_h0.png,/tmp/h/Вильена_h1.png" \
    --output /tmp/one.png --gap 16 --crop auto
```

`stack_images.py` работает внутри Blender (numpy есть, PIL нет):
режет по альфе, оставляет 4px полей, склеивает вертикально с цветным
разделителем, печатает `STACK_JSON` с итоговым размером.

Результат: `2984×258` вместо `3000×620` — полезная детализация по высоте
выросла вчетверо, а по горизонтали вдвое против панорамы.

**Подпись к картинке обязательна** — иначе пользователь не поймёт порядок:

```
Верхняя полоса — левая половина ряда (X 0…67)
Нижняя полоса — правая половина (X 67…134)
Порядок: слева направо, сверху вниз.
```

Если модулей всё ещё мало видно — скажи пользователю, что можно переделать
полосами 4 вместо 2 (детализация по горизонтали удвоится).

## Порядковый номер → координата: не угадывать

Пользователь описывает модуль **порядковым номером**:

> *«Мне нужна седьмая модель слева из первой картинки — стол с закрытыми
> ящиками, и 11-я модель — стеллаж с открытыми полками»*

На первый взгляд всё ясно. На деле для ряда из десятков модулей номер
**неоднозначен**, и цена ошибки высокая: вырезана не та мебель **и уже
загружена на Drive**, откуда её потом надо вычищать.

Источники неоднозначности:

1. **Граница между полосами.** Склеенная картинка — две полосы; попадает ли
   «7-я» в верхнюю или в нижнюю, зависит от того, где проходит стык.
2. **Что считать модулем.** В зоне X 0–13 у Вильены около 9–11 мелких низких
   блоков, но человек может считать их одним «тумбным блоком» или по одному.
3. **Открытые двери.** Разделение на полосы не совпадает с разделением по
   модулям: створка входит в X соседа, и визуальный «модуль» на картинке
   не равен кластеру объектов.

### Правильная процедура

**Не подбирай номер сам.** Добавь координатную разметку и попроси диапазон:

```bash
for i in 0 1; do
  blender --background --python render_parts.py -- \
    --models-dir <dir>/input --out-dir /tmp/tick --select "Вильена" \
    --samples 40 --res-w 2600 --res-h 800 --view front \
    --slice "$i/2" --ticks 5 --suffix "_t$i"
done
```

`--ticks N` рисует вертикальные метки с подписями через каждые N единиц
вдоль главной оси (`add_axis_ticks()`: mesh-линия + FONT-объект с числом,
повёрнутый лицом к камере).

Ответ пользователя сводится к одному числу: *«блок примерно от 7 до 10»*.

### ⚠️ Границы меток — по всей модели, не по срезу

Первая реализация считала `lo`/`hi` из габаритов **отфильтрованных** объектов,
и вторая полоса начиналась снова с нуля: подписи «0…65» и «0…70» в двух полосах
невозможно сопоставить. Исправление — передать глобальные границы:

```python
# ДО среза — габариты всей модели
g_lo, g_hi = scene_bounds(objs)
full_range = (g_lo[axis_idx], g_hi[axis_idx])
# ...
add_axis_ticks(objs, cfg, center, size, full_range)
```

Не потеряй аргумент `full_range` при доработках — иначе подписи снова совпадут.

### Подстраховка

Даже с координатами пользователь может ошибиться. Поэтому:

1. Вырежи выбранные диапазоны **отдельно**, без загрузки на Drive
   (`--skip-upload` в `process_file.py` либо прямой вызов `split_selected.py`).
2. Отрендери выбранное и **покажи пользователю**.
3. Только после подтверждения — грузи в `<папка>/<имя_файла>/models` и `renders`.

## Грабли в самих скриптах (исправлены, не повторять)

**1. Рефакторинг кадра ломает сигнатуру.** При выносе логики кадра в
`_render_scene()` остался лишний позиционный аргумент (`size`), и рендер
падал с:

```
_render_scene() takes 5 positional arguments but 6 were given
```

`render_iso()` при этом отдавал `ok=False` и **продолжал работу** — ошибка
видна только в поле `error` в `RENDER_JSON`. После любого рефакторинга
рендера прогоняй и `smoke_test.py`, и рендер с новым флагом (`--ticks`,
`--slice`, новый `--view`).

**2. Склейка полос разной ширины.** При разной ширине полос фолбэк брал
**первый столбец** и растягивал его на всю ширину — полоса выходила мусорной,
и в склейке молча пропадала целиком. Правильно — дополнять прозрачностью
по бокам:

```python
crop = np.zeros((h, width, 4), dtype=np.float32)
x0 = (width - w) // 2
crop[:, x0:x0 + w] = a
```

**3. Ссылка на несуществующий срез.** В примерах этого файла встречается
`Вильena_h1.png` с латинской `l` вместо кириллической `л` — файл не найдётся,
`stack_images.py` молча склеит одну полосу. Копируй команды, а имена файлов
перепроверяй по `ls`.

## Открытые двери: почему они ломают разделение по оси

**Ключевая находка сессии.** На рендерах Вильены створки распахнуты под
разными углами и **выходят в X-диапазон соседнего корпуса**. Следствия:

1. зазор «между корпусом и торчащей дверью» неотличим от зазора «между модулями»;
2. смещение центров объектов по X бессмысленно — дверь шкафа №5 оказывается
   рядом с корпусом №4;
3. любой разрез по X отделит створку от её хозяина.

Именно поэтому и зазоры, и перекрытие дали мусор. Это **не** тупик инструментов,
а структурное свойство модели.

### Три способа это обойти — предлагай все три

| | Подход | Когда выбирать |
|---|--------|----------------|
| **1** | **Восстановить створки по петлям.** У двери есть ребро крепления; привязать к корпусу, чей X ближе к петле. Дальше резать только корпуса | нужен полностью автоматический результат |
| **2** | **Пользователь размечает границы.** Он называет стыки по картинке, ты режешь по этим X. «Зависшие» створки привязать по его указанию | пользователь уже смотрит на рендер, минимум возни |
| **3** | **Закрыть двери перед разделением.** Повернуть створки в закрытое положение → корпуса станут плотным рядом с чёткими стыками, зазоры заработают | допустимо менять исходную модель |

Спроси, какой вариант, и **отдельно предупреди про 3**: он изменяет исходную
модель, и это нужно явное согласие.
