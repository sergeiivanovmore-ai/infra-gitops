# reverse-proxy/conf.d

Репозиторий — единственный источник истины для этих vhost'ов.

- деплой (`scripts/deploy-infra.sh`) копирует все `*.conf` отсюда в
  `/opt/docker/reverse-proxy/conf.d/`;
- затем каталог сверяется с этим списком: `*.conf`, которых здесь нет, уводятся в
  `/opt/docker/backups/reverse-proxy-conf/<имя>.retired-<дата>` и больше не читаются nginx;
- поэтому правка файла прямо на хосте будет откатана следующей выгрузкой — новый vhost
  добавляется сюда, через PR;
- `nginx -t` выполняется после копирования: если проверка не прошла, деплой завершается
  с ошибкой и конфигурация не применяется. Раньше это был только `WARN`, и правки
  молча не доезжали до nginx.

Сертификаты (Let's Encrypt) и сами домены под управление не входят: vhost ссылается на
`/etc/letsencrypt/live/<домен>/`, а выпуск сертификата — отдельная операция.

Nginx читает только файлы с суффиксом `.conf`: `*.disabled`, `*.save`, `*.bak-*`
безопасно лежат рядом, но лучше держать их в `/opt/docker/backups/`.
